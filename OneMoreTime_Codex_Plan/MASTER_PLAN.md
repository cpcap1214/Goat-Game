## 1. 產品目標與範圍

### 1.1 遊戲一句話

第一次留下位置或行動；第二次與上一輪的自己合作，前往單靠一隻角色到不了的地方。

暫定專案代號 `OneMoreTime`，顯示名稱暫定「再咩一次」。最終主角概念是山羊；這個 demo 先使用 Sunny Land 的狐狸和場景素材，不需要製作山羊美術，也不改成一般狐狸打怪遊戲。

### 1.2 固定的設計要求

| 項目 | 規格 |
|---|---|
| 類型 | 單人、2D 橫向平台跳躍＋輕解謎。 |
| 主題 | 再一次 / One More Time。 |
| 必要限制 | 玩家至少重複一次相同情境，不能第一輪直接完成主要障礙。 |
| 翻轉 | 第二輪不增加跑速、跳高、生命或攻擊力；第一次留下的位置與時序改變第二輪玩法。 |
| 內容 | 正式可玩關卡只有四關；主選單、結尾和開發測試場景不算第五關。 |
| 美術 | Sunny Land；狐狸暫代山羊；同一套明亮山地素材即可。 |
| 核心能力 | 定格記憶、最近最多 10 秒的軌跡記憶。 |
| 記憶數量 | 共用一個欄位，一份定格或一份軌跡，不能同時保留兩份。 |
| 目標平台 | 先在 Unity Editor 可玩；規劃桌面瀏覽器 Web／WebGL 建置作為 itch.io 交付目標。這是本計畫的預設，不表示使用者已完成平台設定。 |
| 操作 | 鍵盤；不製作手機觸控或手把完整支援。 |
| 體驗目標 | 新玩家約 10–15 分鐘完成，這是待測試目標，不是實測數據。 |

不做：戰鬥、敵人 AI、二段跳、衝刺、爬牆、攀邊、多份殘影、推箱子、斜坡物理、旋轉平台、技能樹、存檔系統、帳號、連線、排行榜、課金、時間軸編輯器、完整世界倒帶。

### 1.3 四關的學習曲線

1. **L01 定格**：留下位置，變成跳板。
2. **L02 機關**：留下持續作用，壓踏板並幫助越過高牆。
3. **L03 軌跡**：留下動作，搭乘過去的自己並再次起跳。
4. **L04 綜合**：留下路線和等待時間，依序開門，配合崩塌平台通行。

開發順序不是遊玩順序：先完成 L01，再驗證最有風險的軌跡與 L03，之後做 L02、L04。正式遊玩仍為 L01 → L02 → L03 → L04。

## 2. 遊戲規則：不得自行改動

### 2.1 準備輪與利用輪

`Preparation` 準備輪：沒有殘影，玩家探索、走跳、錄製。E 或 Q 成功保存記憶後，本輪立即結束，重置關卡並回到起點。

`Execution` 利用輪：存在一份已保存的記憶。玩家利用它過關；不能保存新記憶，也不能踩著舊記憶覆寫更高的位置。死亡或 R 重試只重置本輪，不會刪除或覆寫保存資料。

遊戲內選單提供「重新錄製」，確認後清除記憶、重置所有機關、回到準備輪。這是遊戲操作上的防誤刪確認，不是要求開發過程不停向使用者確認。

進入新關卡會清除上一關記憶。相同關卡兩輪的靜態地形一致，只有玩家留下的記憶改變解法。

### 2.2 定格記憶

準備輪中按 E：保存角色當下的世界座標、朝向與視覺姿勢；提交記憶後立刻結束本輪，重置並生成固定殘影。

- 角色可以在地面或半空定格。
- 不是停止全世界，不透過 `Time.timeScale = 0` 實作能力。
- 固定殘影沒有重力、不移動、不被尖刺殺死，也不被活角色推動。
- 上緣是固定大小的單向支撐面，可由下方穿過、從上方站上去。
- 在踏板有效位置定格，可持續壓住踏板。
- 殘影不跟著角色動畫改變碰撞大小，尾巴、耳朵都不影響可踩範圍。
- 利用輪的 E 無效，只顯示「要改變記憶，請選擇重新錄製」。

### 2.3 軌跡記憶

L03／L04 開放 Q 保存最近最多 10 秒。準備輪一開始便錄製，不需要另按錄影開始；Q 的意思是「保存目前窗口並結束本輪」。

- 保存的是已解算的位置和視覺資料，不是重新模擬按鍵。
- 不必錄滿 10 秒；最低有效長度暫定 0.25 秒，過短時顯示提示而不結束本輪。
- 超過 10 秒只保留最近 10 秒；不自動截斷成第一個 10 秒，不丟棄等待。
- 回放使用原世界座標。窗口的第一個點可能不在出生點，不能平移整段路徑到出生點。
- 利用輪開始時狀態為 `Ready`，只顯示路徑和起點輪廓，沒有支撐或踏板效果。
- 玩家可以先移動至方便搭乘的位置，再按 Q 啟動。
- Q 啟動後從快照的相對時間 0 開始播放一次，不倒播、不循環、不在本輪再次啟動。
- 回放完畢進入 `Finished`，先停用支撐／踏板效果，再播放短暫消散；最後一幀不變成永久跳板。
- 回放時角色和殘影使用同一個固定遊戲時鐘；開啟暫停選單時都停止。
- 玩家不能被殘影的側面推擠，只能由頂部支撐。

### 2.4 死亡與重試的完整語義

| 當前情境 | 行為 |
|---|---|
| L01／L02 準備輪死亡 | 回到本關起點，沒有記憶；不自動在死亡處定格。 |
| L03／L04 準備輪死亡 | 凍結死前有效軌跡，進入小型死亡選擇畫面：Q 保存死前軌跡、R 重新嘗試。死亡後不再增加樣本；過短則禁用 Q。 |
| 任一利用輪死亡 | 自動重置玩家和世界，保留原記憶；定格立即生成，軌跡回到 Ready。 |
| 準備輪按 R | 丟棄本輪未保存軌跡，重置為新的準備輪。 |
| 利用輪按 R | 保留原快照，世界重置；軌跡時鐘與使用次數一起重置。 |
| 選擇重新錄製 | 經遊戲內確認後刪除快照，全部重置為準備輪。 |
| 通關或回主選單 | 清除本關所有記憶和本輪資料，不跨場景保留殘影。 |

死亡軌跡只到最後一個有效、未致死的模擬姿態；不要保存重生瞬移或出界後的長距離落下。手動 Q 保存則可包含本固定步的有效最終姿態。

### 2.5 操作表

| 輸入 | 準備輪 | 利用輪 |
|---|---|---|
| A／D、左右方向鍵 | 水平移動 | 水平移動 |
| Space | 跳躍；可短按／長按調整高度 | 相同跳躍，數值完全不變 |
| E | 定格保存並結束本輪 | 不覆寫，顯示重新錄製提示 |
| Q（L03／L04） | 保存最近最多 10 秒並結束本輪 | Ready 時開始回放，Playing／Finished 時不重啟 |
| R | 不保存，重新準備 | 保留記憶，重試利用輪 |
| Esc 或 P | 暫停選單 | 暫停選單 |

按鍵在 Update 收集並鎖存，固定步只消耗一次。不要讓保存那一次 Q 連帶在重生後觸發回放。暫停、死亡和重生後清除殘留輸入；失去視窗焦點時清除移動／跳躍並暫停，避免切回遊戲仍在走。

同一步有多個請求時採單一入口處理：致死 → R 重試 → E 定格 → Q 保存／播放；死亡當步不再通關，只有存活且沒有重置請求時才接受終點。選單控制優先於遊戲控制。

## 3. 技術基線與素材

### 3.1 版本與依賴策略

先讀 `ProjectSettings/ProjectVersion.txt`、`Packages/manifest.json`、可用時讀 `packages-lock.json`。既有 Unity 專案沿用實際版本和渲染管線，不升級大版本，不擅自改 URP／Built-in，不要求重新建立專案。

若是全新空工作區且本機有 Unity，使用已安裝且能建立 2D 專案的穩定版本；記錄完整版本號，不猜「最新版」。若 Unity 不存在或授權／必要模組不可用，列出確切阻塞，完成可安全進行的原始碼與工具工作，不製造一個假裝已經可開啟的專案。

沿用既有輸入系統；只啟用一個實際輸入後端。新專案優先採已可用的官方 Input System；若環境只有既有 Input Manager，就用相容的單一 adapter。遊戲邏輯只依賴 `IPlayerInput`，同時提供測試用輸入來源。不得為此安裝第三方角色控制器或大框架。

### 3.2 Sunny Land 使用規格

素材作者頁目前列出角色、敵人、道具、特效和音樂，並分別列出原始素材檔案與不同引擎範例；不能因此假設工作區已經有 Unity Prefab 或有所有動畫。[S2]

階段 0／1 必須盤點實際素材：

- 真實資料夾、圖像尺寸、切片資料、地形格尺寸、Sprite GUID／子資產、角色動畫影格。
- 優先使用使用者已匯入的內容。已有正確切圖時，不重新切割破壞 Sprite 引用。
- 缺素材時建立明確標示的白盒替代，只允許用來驗證玩法；報告註明仍未完成 Sunny Land 整合。
- 下載需要授權或帳號操作時，列出實際缺項，不繞過付費、不猜測下載網址。
- 保留實際取得版本的授權檔；美術、音樂、字型分別記錄，不假設不同來源同一授權。作者頁面目前標示 CC0，但實作時仍核對所用檔案。[S2]
- 這份規格包不附 Sunny Land 素材，也不附任何字型檔。

採 `Sprite (2D and UI)`、需要時使用 `Multiple`。像素圖採 `Point` 過濾以避免模糊；PPU 代表每個世界單位對應多少像素，應依實際素材統一比例，不能把所有圖都假定為 16×16。[S6]

角色視覺是 `Visual` 子物件，與固定碰撞體、腳底原點、殘影背部支撐面分離。換山羊時只替換視覺／動畫資料，不改動角色能力和四關幾何。

### 3.3 尺度與手感：原型起始值

世界座標以角色腳底為原點；地板表面 y=0 時，站立角色的 root.y 也是 0。下面不是素材像素尺寸。

| 參數 | 初始值 | 備註 |
|---|---:|---|
| 固定模擬步長 | 0.02 秒 | 軌跡與角色共用；實作後不要中途變更。 |
| 最大水平速度 | 6.0 單位／秒 | 準備輪與利用輪一致。 |
| 地面加速度／減速度 | 60／80 單位／秒² | 初始值，依操作測試調整。 |
| 起跳速度 | 14 單位／秒 | 起跳時覆寫垂直速度，不疊加殘影速度。 |
| 重力大小 | 32 單位／秒² | 解析式最大高度約 3.06；以實測為準。 |
| 終端落速 | 18 單位／秒 | 防止無限制加速。 |
| 跳躍寬限 | 0.10 秒 | 離開平台後的短暫可跳窗口。 |
| 跳躍輸入緩衝 | 0.12 秒 | 落地前短暫接受跳躍輸入。 |
| 角色碰撞體 | 約 0.70 寬、1.00 高 | 視覺可稍有不同，平台可踩區不得隱藏。 |
| 殘影支撐面 | 約 1.10 寬；腳底上方 0.90 | 高度固定，不隨動畫改變。 |
| 幾何容差 | 約 0.02 單位 | 避免邊緣抖動，不可用過大 snap 補足不可達距離。 |

短按跳躍可在放開按鍵時削減向上速度；最大高度以長按測定。關卡設計使用實測最大跳高 `H`、最大實用跳遠 `D` 與支撐面高度 `B`，不能因為某關做壞而只偷偷提高那關的跳躍數值。

## 4. 移動、殘影、錄製的實作架構

### 4.1 移動策略：先求可靠，範圍限定矩形地形

新專案的預設是可控制的 2D kinematic motor：角色有固定 BoxCollider2D、Kinematic Rigidbody2D，關閉內建重力／旋轉，用自己的速度和 world casts 解算移動，將最後的位置提交給 Rigidbody2D。不要把自訂位移與 Dynamic 剛體的自動重力／碰撞修正混在一起。

本 demo 只有軸對齊地面、牆、天花板和頂部單向殘影，不做斜坡／旋轉／真實重量模擬。這讓平台承載和記錄使用同一份可預測姿態。

若專案已有穩定的角色控制器，可以保留；但必須先證明它通過本規格的移動平台、無額外速度繼承、單向支撐和重播測試，並在 `ARCHITECTURE.md` 記錄差異。不為了符合類別名稱而重寫有效系統。

**殘影的支撐由角色 motor 唯一負責**：`EchoSurface` 提供上一固定步與本固定步的頂面位置、寬度和位移，角色解算站立／落地。殘影不再用另一套非 trigger 實體碰撞器同時推角色，避免同一位移被套兩次。需要感應器時使用 trigger 或邏輯區域。

不能因為 `MovePosition` 移動了殘影，就認定角色會可靠搭乘。該 API 的實際位移發生在物理更新，官方也說明其適用 kinematic 的情境；採該路線時必須釐清時序，不能在呼叫後立刻把 transform 當成已更新的姿態。[S3]

### 4.2 單一模擬時鐘與資料流

建議用一個 `SimulationDriver.FixedUpdate` 明確呼叫系統，而不是依賴許多 MonoBehaviour 的偶然執行順序：

1. 處理狀態切換和本步唯一操作請求；若進入重置，不再執行舊一輪的剩餘步驟。
2. 若回放啟動，計算殘影當前及下一姿態與支撐面位移。
3. 讀取本固定步的輸入，解算角色的平台承載、水平／垂直移動、跳躍和 world 碰撞。
4. 處理殘影頂面的相對運動落地判斷，提交最終角色位置；完成危險區掃掠／出界判斷。
5. 依角色與殘影最終腳底位置更新踏板，更新門的下一步碰撞狀態及崩塌計時。
6. 只在 Preparation 且存活時記錄最終姿態；處理保存、死亡和終點事件。
7. 更新顯示資料；相機、畫面補間、特效只讀模擬結果，不反向修改物理狀態。

存檔動作可延後到本步有效姿態完成後提交，但輸入優先序和「只處理一次」必須一致。記錄資料不能取自渲染插值過的 transform。

### 4.3 移動殘影搭乘的必要條件

- 站在支撐面上的角色，每步只接收一次平台位移。
- 上升、下降、水平、斜向都要穩定，不以角色與平台做 Transform parent 的方式代替解算。
- 已站立時要跟隨下降平台，不是平台一下降就因為向上接觸消失而掉落。
- 從下方穿過時不吸附到平台頂部；判斷上一幀腳底與上一幀平台、下一幀腳底與下一幀平台的相對高度及水平重疊。
- 從上方接近頂面，且相對運動跨越頂面時才落地；不要只看角色在世界座標中的垂直速度。
- 離開邊緣、主動起跳、平台消散、重試後清除支撐引用。
- 起跳速度固定為角色自己的 jump speed，不額外加上殘影速度；已傳遞的本步位置偏移不能再重複套用。
- 搭乘位移仍做 world casts，不能把玩家帶進牆或天花板。無法完整承載時停止侵入並解除不成立的支撐，不瞬移、不彈射。
- 關卡不設計需要殘影壓碎玩家的情境。被夾住時玩家可 R，不產生軟鎖。

### 4.4 錄製資料與快照

概念資料契約；依現有程式調整名稱即可：

```text
MemoryKind: None | Freeze | Trace
RunPhase: Preparation | Execution
FlowState: Playing | Paused | Transitioning | DeathReview | Completed
PlaybackState: Ready | Playing | Finished

RecordedFrame:
  timestamp               // 原始錄製時鐘；匯出快照後改為從 0 起算
  position                // 模擬世界座標；腳底原點
  facing                  // -1 或 +1
  animationState          // Idle/Run/Jump/Fall 等可重現狀態
  animationFrame          // 或可穩定對映的動畫相位
  grounded                // 回放踏板判斷和視覺用途

MemorySnapshot:
  kind
  freezePose              // Freeze 時使用
  frames[]                // Trace 時使用、時間升冪
  duration
  levelId
  isValid
```

錄製使用預先配置的循環緩衝區。0.02 秒步長下，含起訖點的 10 秒窗口最多需要 501 個樣本；依時間戳裁切，不把「500 個間隔」和「500 個端點」混淆。複製為快照後不可再被新一輪 ring buffer 改寫。

必須防禦：0／1 個樣本、非有限座標、非升冪時間、過短軌跡、保存與重生在同一步、暫停後重複按 Q、長時間準備而記憶體不斷增長。

回放可以插值位置，但遊戲支撐與感應也必須使用同一個模擬姿態。視覺可再補間；不能用另一個 Update 時鐘決定可踩位置。記憶只存在記憶體，不寫磁碟、不做跨遊戲存檔。

### 4.5 殘影必須是乾淨的 Prefab

不要直接複製整個活角色 GameObject 來當殘影。殘影只包含視覺、`EchoSurface` 和必要的邏輯感應資料，不得帶上 `PlayerMotor2D`、輸入、錄製器、死亡處理或第二個相機。

### 4.6 世界重置順序

`RunManager` 是唯一重置入口，定格、軌跡保存、死亡、R 和重新錄製共用此流程：

1. 鎖住遊戲輸入；取消崩塌倒數、門動畫回呼與延遲事件，增加本輪 generation id。
2. 解除角色支撐、停止回放並停用所有殘影效果。
3. 依操作決定保留／刪除／提交不可變快照；重置感應器集合。
4. 重置門、崩塌平台和其他動態環境；恢復初始碰撞。
5. 角色移回出生點、速度清零；清除跳躍緩衝、coyote、死亡旗標和輸入。
6. Freeze 立即建立有效支撐／踏板作用；Trace 建立無作用 Ready 預覽。
7. 重新計算固定殘影對踏板的狀態；相機回起點；下一固定步恢復遊戲。

不能以同時執行數次 LoadScene 或未取消的 coroutine 重置，導致本輪剛恢復的平台被上一輪計時器再次刪除。

## 5. 可重用物件與機關

### 5.1 地形與支撐分類

| 類型 | 活角色碰撞 | 殘影行為 |
|---|---|---|
| World：地面、牆、天花板 | 正常阻擋 | 已錄製軌跡不被當輪 world 重新推動。 |
| EchoSurface | motor 解算頂部單向支撐 | 不使用實體側面推擠。 |
| Hazard：尖刺／出界 | 死亡 | 不改變回放資料。 |
| PressurePlate | 腳底符合區域才壓下 | 依記憶種類與回放狀態判斷。 |
| Goal | 存活時接觸通關 | 不觸發通關。 |
| Decoration | 無碰撞 | 無作用。 |

建立所需 Layer 時找未使用欄位，不覆寫既有 Layer。Sorting Layer 與 Physics Layer 分開記錄，不能混用。

### 5.2 踏板 PressurePlate

先採邏輯區域，不做真實重量。判斷腳底在 plate top 容差內、水平重疊，且是有效站立姿態；角色只是從上空經過不算壓下。

活角色、有效 Freeze、正在 Playing 的 Trace 可壓踏板；Ready 或 Finished 的 Trace 不可。Freeze 在上方懸空不算重量。多個合法來源同時壓下時，不會因一個來源離開就錯誤關門。

感應器只讀角色資料，不推動位置，不直接操控 RunManager。重置時清空所有來源並重算，避免不存在的殘影永遠壓住踏板。

### 5.3 門 LinkedDoor

每扇門有明確的踏板引用和可見連線／符號。踏板啟動時開門，離開時關門，沒有長時間自動保持開門。

機關狀態與視覺動畫分開：關門碰撞不因漂亮動畫延遲到足以衝過去。若活角色已在門洞範圍內，暫緩實體關閉至角色離開，避免門生成在玩家體內；範圍只包含實際門洞，不擴大成遠距離自動開門。

佔據門洞只能保護當下通過，不讓任意殘影或已離開的角色保持整條路開放。正確重算能避免第二關被快速離開踏板的角色繞過。

### 5.4 崩塌平台 CrumblingPlatform

只有活角色實際站上平台才開始倒數，初值 0.65 秒；不是角色碰到側面，也不是殘影路過就倒數。倒數時裂紋與閃爍，時間到才關閉實體碰撞並消散。

平台在本輪不自動恢復，R／死亡重置才完整恢復。使用模擬時鐘或可取消的倒數，不使用重生後還繼續執行的舊 coroutine。

第四關崩塌段後一定有永久安全落腳點。不得讓玩家在必須等門 B 的位置繼續被倒數逼死。

### 5.5 危險區與終點

出界由清楚界限／KillZone 控制；不可在場景外無限制落下。危險區死亡會走同一套狀態機。終點只接收活角色，不以「已重生一次才啟用」硬鎖來假裝符合主題，必須靠關卡幾何和機關真正要求重複情境。

## 6. 四關白盒規格

以下座標以腳底為原點、地面 y=0、實測 H 約 3 為前提，僅作為生成器的初始配置。Codex 必須自己測試並在 `LEVELS.md` 記錄調整後座標。所有修正維持同一套全局角色參數。

### 6.1 L01_Freeze｜借我踩一下

**解題重點：定格高度要能被下一輪踩上。**

初始佈局：寬約 20 單位；出生點 (2,0)；地面至 x=13；右側高台從 x=13 延伸至 20，頂面 y≈4.5。終點位於高台右側。主要謎題區無可額外墊高的箱子、敵人或中繼平台。

正常解法：跳向高台，在 x≈12、腳底 y≈1.5 定格，讓殘影頂面約 y=2.4。重生後跳上殘影，再跳到 y≈4.5 高台。

幾何條件：直接跳高 H < 高台高度；殘影頂面可從地面到達，而且由頂面可跳到高台。不要教玩家在最高點定格，因為背部可能比最高可達腳底還高。

畫面提示依進度出現：

1. 「方向鍵移動，空白鍵跳躍。」
2. 在高牆前：「按 E，留下一個下一次踩得到的自己。」
3. 重生後：「從上方踩住殘影，再跳一次。」
4. 多次踩不到時：「留下的位置，可能太高了。」

驗收：無記憶無法通關；中等高度定格可通關；太高的定格不自動瞬移修正；R 保留記憶；重新錄製可恢復準備輪。

### 6.2 L02_Pressure｜幫我留在這裡

**解題重點：同一個固定殘影同時是重量和起跳點。**

初始佈局：出生點 (2,0)；踏板中心 x≈10.8、頂面約 y=0.1、寬約 1.4；右側高台從 x≈12 開始、頂面 y≈3.5；門位於 x≈13 的高台通道，延伸到天花板，無法翻過頂端。終點在門後。

正常解法：準備輪踩踏板看見門開；離開門即關。站在踏板上 E，下一輪殘影持續壓住踏板。利用背部約 0.9 的高度跨上高台，穿過門。

必須避免：plate 本身墊高到普通跳躍就夠；門距離近到離開踏板還能衝過；關門動畫讓碰撞延遲；門上方能翻越；門被殘影側面或路徑預覽誤觸發。

驗收：一個固定殘影完成兩個用途；玩家在空中定格不壓踏板；不同輪次的門狀態重置；普通活角色離開踏板無法憑時間差單獨通關。

### 6.3 L03_Trace｜跳上昨天

**解題重點：先讓下一輪站上來，再用上一輪的跳躍把它帶高。**

初始佈局：寬約 22；地面 y=0；出生點 (2,0)；錄製／搭乘位置在 x≈12.8 的安全地面；出口平台從 x≈14 開始，頂面先設 y≈6.45；無中間平台。

正常錄製：走到出口下方 → 等約 2 秒 → 原地長跳一次 → 落地後再等約 0.5 秒 → Q 保存。通常 5–7 秒就足夠，不需錄滿 10 秒。

利用輪：走到搭乘區 → Q 播放 → 趁過去的角色等待時站上背部 → 殘影起跳把角色帶高 → 接近合適高度時往右再次起跳，落到出口。

設計不等式（只用來開始測試）：可從地面站上的固定殘影頂面不應高於 H，因此固定方案最高約到 2H；移動殘影可先在地面讓角色上去，再把頂面帶到 H+B，活角色再次跳到約 2H+B。目標平台要位於 2H 之上、2H+B 以下，且兩邊留出容錯。H≈3、B≈0.9 時，先試 y≈6.45。

必須實測 coyote、角色碰撞體、單向面解算和實際積分；不能只靠解析式就宣稱定格解不掉。若時間窗口太窄，優先調整全局支撐面與平台高度的合理裕量，不把跳躍改成第三關專屬強化。

提示：

- 「先等一下，再跳。下一次的你需要時間站上來。」
- 「Q 保存最近最多 10 秒，並開始下一輪。」
- Ready：「準備好後按 Q，讓過去的自己再走一次。」
- 多次上不了車：「錄製時，多留一點站上去的時間。」

驗收：回放可搭乘；定格單獨無法到出口；殘影側面不推人；Q 不循環；結束不留永久平台；普通 R 不要求玩家重新錄製。

### 6.4 L04_Timing｜這次換你等我

**解題重點：第一次要刻意等待，安排第二次通行的時序。**

採上下兩條可互相看見的路。上層是解題通道；下層是錄製通道。下層不是通往出口的抄近路。

初始配置草案：

| 元件 | 初始位置／條件 |
|---|---|
| 出生 | 上層 (2,5)。 |
| 下層入口 | 起點附近的一個明顯下落分岔；上層仍能用普通跳躍跨過。 |
| 下層地面 | y=0，踏板 A 中心 x≈6，B 中心 x≈18。 |
| 上層路徑 | 頂面 y=5；門 A x≈10，門 B x≈24；終點 x≈28。 |
| 崩塌區 | 上層 x≈13–17；長度配合實測 D，可分成少量小平台。 |
| 安全落腳點 | 崩塌區後至門 B 前的永久平台，足夠停下等待。 |
| 上下層分隔 | 有實體分隔與下層天花板，只在起點提供下落入口。 |
| 門的防繞過 | 門連接上下實體邊界，不能從上方、下面或右側繞過。 |
| 崩塌區下方 | 狹窄死亡區，避免落到下層天花板頂部後從門下偷走；不得碰到正常下層錄製路線。 |

不能只依賴下層到上層的高度差：移動殘影可能再次把玩家抬高。必須真的用分隔幾何阻止在門後爬回上層。起點附近即使可以借殘影返回上層，也只能回到門 A 前，不可繞過核心機關。

玩家自己錄製的參考時序（不是遊戲自動代跑）：

| 回放相對時間 | 下層殘影 | 上層活角色 |
|---|---|---|
| 約 0–1 秒 | 從起點落下並前往 A。 | 跳過下層入口，接近門 A。 |
| 約 1–3 秒 | 在 A 等待。 | 通過門 A。 |
| 約 3–5 秒 | 移動到 B。 | 穿越崩塌區，抵達永久落腳點。 |
| 約 5–8 秒 | 在 B 等待。 | 通過門 B，抵達出口。 |

精確時序以生成後幾何實測，整條可用錄製須落在 10 秒內並保留裕量。玩家可更早啟動回放、調整自己的路線，不要求踩中唯一一幀。踏板等待時間必須由玩家實際停留產生，不由程式替玩家補上。

若只在 A 定格，B 無法開；只在 B 定格，A 無法過；快速經過 A/B 的軌跡應難以支持正常通行；留下合理停留才有清楚可靠的解法。這些要測試而不是只寫在設計說明。

失敗後可提示：「也許，剛剛的你可以多等一下。」不直接顯示標準秒數。第二次玩家主動重新錄製更長停留，即為本關希望產生的學習。

## 7. 專案結構與自動配置

新內容預設放在 `Assets/_OneMoreTime/`，避免改動素材包原始範例。可沿用既有合理結構，但須記錄對應。

```text
Assets/_OneMoreTime/
  Runtime/
    Core/         # RunManager、SimulationDriver、SceneFlow
    Input/        # IPlayerInput、實際輸入 adapter
    Player/       # PlayerMotor2D、PlayerVisual
    Memory/       # Recorder、Snapshot、EchoSurface、EchoPlayback
    World/        # PressurePlate、LinkedDoor、CrumblingPlatform、Goal、Hazard
    UI/           # HUD、Tutorial、Pause、DeathReview、MainMenu
  Editor/         # 場景、Prefab、素材對映、測試／建置工具
  Config/         # PlayerTuning、GameCatalog、LevelConfig、AnimationLibrary
  Prefabs/
  Scenes/
    MainMenu.unity
    L01_Freeze.unity
    L02_Pressure.unity
    L03_Trace.unity
    L04_Timing.unity
    Ending.unity
    Dev_Playground.unity   # 不加入正式 build
  Tests/
    EditMode/
    PlayMode/
  Generated/      # 只容許生成器管理的資產
Docs/Codex/
Tools/             # Editor 偵測、執行測試與 Web 打包
Artifacts/         # 執行紀錄和建置產物；不當作 Unity 原始資產
```

採少量明確的模組，不建立 ECS、全域事件匯流排、依賴注入框架或無用途的泛用服務。可配置數值用 ScriptableObject 或 Inspector 欄位集中管理，不把四關座標散落在角色腳本。

### 7.1 必須建立的 Editor 入口

以下是本專案要實作的入口，不是 Unity 已經內建的方法：

- `Tools/One More Time/Audit Assets`：掃描實際素材與缺失對映。
- `Tools/One More Time/Build or Update Demo`：根據階段／設定建立資產與場景。
- `Tools/One More Time/Validate Demo`：Missing Script、引用、圖層、關卡配置、正式場景清單檢查。
- `Tools/One More Time/Open Playground`：打開開發測試場景。
- `Tools/One More Time/Build Web Demo`：在必要模組存在時生成 Web 產物。

同時暴露對應 public static Editor 方法，方便透過 Unity 的 `-batchmode`／`-executeMethod` 執行；Unity 文件要求這類被呼叫的方法為 static 並放在 Editor 編譯範圍。[S4]

### 7.2 生成器的安全與可重現要求

- 用 Editor API 建立／更新 Scene、Prefab、ScriptableObject、Animator／動畫資料；不憑空手寫大量 Unity YAML、GUID 或套件 metadata。
- 同一階段執行生成器兩次，不能生成第二個玩家、相機、Canvas、門、圖層或重複 EventSystem。
- 維持資產路徑和 GUID；不要為了重建每次刪除整個目錄。
- 工具只修改本專案自己的生成區域；若會覆蓋使用者手動改過的場景，採明確 managed root／layout config 或先建立備份，不靜默毀掉編輯。
- 每階段只建立已實作的內容，不能讓未存在的元件或後續階段類別導致現在無法編譯。
- 先等待腳本編譯完成，再執行場景生成；不要在 AssetDatabase.Refresh 觸發重編譯後假定同個堆疊會順利繼續。
- 不隨意改整個專案的 build scene 清單；本 demo 使用獨立 build 設定或明確自己的場景陣列。
- 每個關卡從 Editor 直接開啟也能啟動，不能因沒先跑主選單就 NullReference。

## 8. 八個開發階段與通過門檻

每階段都要實作當階段測試，不把所有測試拖到最後。詳細可貼提示詞見 `STAGE_PROMPTS.md`。

| 階段 | 實作範圍 | 必須交付的可見成果 | 通過門檻 |
|---|---|---|---|

### 8.1 先做早期 Web 冒煙測試

階段 1 若 Editor 具備 Web Build Support，可先把小測試場景輸出一次，確認工具鏈。缺少模組只記為 Web 阻塞，不阻止 Editor 玩法繼續。最終四關 Web 包仍在階段 7 重新建置和驗證，早期成功不能當作最終成功。

### 8.2 Gate 狀態

每個驗收項只用以下真實狀態：

- `PASS`：已執行指定檢查並有結果。
- `FAIL`：已執行且不符合規格。
- `NOT RUN`：尚未執行；寫出原因和重現步驟。
- `BLOCKED`：缺 Editor／授權／模組／資產／權限等環境條件，且有實際檢查依據。

文件中的狀態不可預填 PASS。需要 GUI 的畫面驗證沒做就寫 NOT RUN；只有靜態程式檢查不等於 Unity 編譯成功，只有編譯成功不等於玩起來正確。

## 9. HUD、視覺與聲音規格

HUD 常態只顯示關卡編號、準備輪／利用輪、目前記憶種類與主要可用按鍵。軌跡模式多顯示最近窗口長度／回放進度，明確寫「最近最多 10 秒」。超過窗口時讓最舊路徑淡出，避免玩家以為最初等待仍會保留。

活角色：保留 Sunny Land 正常外觀。Freeze：冷色、結晶輪廓、頂部水平亮線。Trace：半透明、簡單拖尾、同樣可辨認的頂面。除了色彩還用圖示、輪廓和文字，不能只用顏色分辨是否可踩。

軌跡 Ready 顯示虛線／薄輪廓、明示「Q 播放」，不能看起來已經是實體平台。保存後用短暫記憶特效、重試時用更短淡入；不要讓玩家每次失敗都等完整倒帶動畫。重新可操作的目標約 0.4 秒內，依實際載入方式測試。

教學每次只出一小段；L01 不顯示尚未解鎖的軌跡 UI。按鍵提示必須對應實際 backend。UI 以繁體中文為主；需盤點具有相應字形且可合法使用的字型，不假設預設字型包含中文字。缺字暫時可英文佔位，但最終繁中顯示仍須標成未完成並解決。

先以 16:9、960×540 和 1920×1080 檢查版面。像素取樣保持清楚，PPU／基準解析度按真實素材設定；UI 可讀優先於強行把所有字縮成像素。相機不能因跟著活角色而完全看不到當前重要踏板／門；L04 保留同時理解上下路線的視角。

有適當授權素材才加入跳躍、保存、重生、踏板、門、崩塌和通關音效；沒有適合音效時先做明確的音效事件與少量可合法取得／自製的簡單音效，不拼湊來源不明內容。音樂最多先用一首；音樂與音效有獨立音量控制。

## 10. 測試與 Web 交付

完整案例見 `TEST_MATRIX.md`。最低需分為：純邏輯 EditMode、物理／流程 PlayMode、視覺人工檢查、Web 實際執行。

### 10.1 自動化原則

回放緩衝區、資料窗口、快照不可變性、狀態機和感應器狀態可以單獨測試。平台搭乘、門碰撞、場景切換與四關通關需要 PlayMode。

端到端的正常通關測試透過測試輸入來源執行移動／跳躍／E／Q／R；不能直接把角色 teleport 到終點就聲稱解法已通過。平台單元測試可使用受控 fixture，但要標示不是端到端遊玩。

Unity Test Framework 的命令列支援 `-runTests`、`-testPlatform` 和結果檔等參數；使用工作區實際安裝版本的對應說明，不為了配合範例降級套件。[S5]

一般批次方法可使用 `-quit`；執行非同步測試則不要不經確認就加上可能提早結束 runner 的參數。檢查程序退出碼、XML 是否真的產生、測試數是否大於 0、有無失敗，不能只看有個檔案就寫 PASS。

不要同時以第二個 Unity 開啟同一個被 Editor 鎖住的專案；若已開啟且有可用 Editor 工具就用它，否則記錄需要釋放的鎖，不強制終止使用者進程。

### 10.2 要實作的命令包裝

Codex 建立可實際使用的環境檢測和腳本，找出真實 Editor 路徑後寫進 `BUILD.md`。不要把未替換的 `<Version>` 或硬編碼開發者機器路徑留作唯一交付方式。

建議命令介面（由本專案實作，不是現成檔案）：

```text
python3 Tools/omt.py audit
python3 Tools/omt.py generate --phase 3
python3 Tools/omt.py validate
python3 Tools/omt.py test --mode edit
python3 Tools/omt.py test --mode play
python3 Tools/omt.py build-web
python3 Tools/omt.py package-web
```

wrapper 可接受 `UNITY_EDITOR` 覆寫；檢查 executable、專案路徑、必要模組、已開啟專案鎖。失敗回傳非零，記錄命令和 log；不偷偷下載 Unity、不修改系統 PATH，不啟動不受控的常駐服務。

### 10.3 Web 和 itch.io 交付

最終產物目標 `Artifacts/Web/` 和 `Artifacts/OneMoreTime-Web.zip`。正式場景清單包含主選單、四關與結尾，不含 Dev_Playground 或測試 assets。

ZIP 根目錄直接有 `index.html`，其引用的 Build／TemplateData 等檔案相對路徑保持完整，不再套一層外資料夾。itch.io 的 HTML5 交付需要 index.html 和所需檔案，路徑及檔名大小寫必須正確。[S7]

優先用少依賴的 Web 設定完成一次真實載入；壓縮設定要與 HTTP server 一致。初次可先使用未壓縮建置排除服務端 Content-Encoding 差異；若更改壓縮，重新實測，不聲稱 Gzip／Brotli 天然可在任何主機運作。[S7]

透過本機 HTTP 而非只雙擊 index.html 測試：載入、點擊啟動音效、鍵盤焦點、失焦暫停、R、Q、場景切換、完整四關和結尾。記錄實際瀏覽器／版本／裝置、首次載入與尺寸、FPS／frame time觀察；沒有量測不填漂亮數字。

沒有可用瀏覽器時仍可建置，但瀏覽器驗證必須標 NOT RUN。缺 Web 模組則提供 Editor 可玩成果和確切 blocker，不能生成一個只有 HTML 空殼的 ZIP 假裝完成。

交付只到可供使用者上傳的檔案與操作說明。未被明確要求不得登入帳號、建立公開頁面、發布／覆蓋 itch.io 遊戲或推送 Git 遠端。

## 11. 最終完成定義

以下缺一項，都不能籠統聲稱完整 demo 已驗收：

1. Sunny Land 狐狸與場景已實際整合；所有必要引用有效，沒有 Missing Script。
2. 只有一份記憶；定格和軌跡互斥；利用輪不能覆寫。
3. 兩輪角色數值不變，四關依正確順序可完成。
4. 四關的第一輪單獨解法被幾何／機關阻擋，不是終點硬鎖輪數。
5. 固定殘影可靠可踩，移動殘影水平／升降／起跳可靠，不雙重承載或彈射。
6. 10 秒窗口、原座標、等待、播放一次、結束消散均正確。
7. 死亡／R 保留已保存記憶；重新錄製刪除；所有環境與計時重置。
8. L02 無單人衝門漏洞，L03 無定格繞關，L04 無上下層抄近路。
9. 主選單、HUD、教學、暫停、死亡選擇與結尾可操作；繁中文字無缺字。
10. 提供實際執行的測試紀錄，未測部分明確列出。
11. 有真實 Web 建置與 HTTP 遊玩驗證，或明確說明 Web 尚未完成而非冒稱完成。
12. 有簡短交付說明：從哪個場景開始、如何一鍵重建、如何測試／建置、已知問題。

## 12. 每階段回覆格式

```text
階段：N／名稱

已實作：實際功能與場景。
主要修改：具體檔案路徑。

驗證：各驗收 ID、PASS/FAIL/NOT RUN/BLOCKED、證據位置。

```

在最後回覆前更新 `Docs/Codex/STATUS.md`。不以「應該正常」「理論上可玩」代替實測結果，也不在缺工具時反覆要求已在本規格明確定義的玩法細節。
